# v1.7.0

PDF_Bookmarks 是 Windows 本地 PDF 书签工具，可独立处理普通 PDF，也适配 Zotero 附件。支持文字/扫描目录识别、JSON 导入编辑、预览校对、拖放和批量写入，保持原 PDF 文件名与路径。

本版将主界面和目录工作台整合为同一窗口的两个标签页，增加本地未完成草稿、撤销/重做、查找筛选与目录树，并加强人工识别区域、栏线和预览定位。面向 **Windows 10/11 x64**；Single 与 Portable GUI 功能相同，均无需安装 Python。发行标题仅使用版本号，七项附件沿用原下划线命名。

## 更新内容

1. **同一窗口、两个标签页**：顶部“主界面 · 预览与写入”和“目录工作台 · 生成与编辑”分工保留，原“生成 / 编辑目录…”入口仍可用。首次进入工作台才创建内容；普通切换不重新识别或载入，保留当前目录、未提交输入、撤销历史、筛选和预览。拖放与编辑快捷键按活动页处理，不影响主界面输入。
2. **保存返回与关闭保护**：“保存 JSON 并返回”成功后回到主界面，载入配对的 PDF/JSON 并自动只读预览，仍须原有确认后才写 PDF。“关闭”按草稿规则关闭本次工作台，顶部标签保留可重开；取消提示继续保留编辑。整窗关闭先检查任务与未保存内容；识别、载入、保存和主界面处理任务互锁，切到后台的工作台仍阻止安装更新。两页沿用各自大小与置顶设置，主界面最小900×650，工作台最小1000×760。
3. **独立本地草稿与恢复**：开启“自动暂存”后，修改停顿约1200毫秒合并暂存；也可点“暂存草稿”或按 Ctrl＋S。未确认条目、未知目标页及未完成输入可暂存至设置文件旁的 `editor_drafts`，不写原 PDF 或正式 `toc.json`。恢复前核对 PDF 路径、大小和修改时间；文件变化或恢复数据损坏时拒绝恢复，保留当前内容与原恢复文件。手动确认替换旧/损坏恢复文件前，先保留其原字节 `.backup.json` 副本。草稿不是正式可写入目录，也不是完整撤销历史备份。
4. **撤销/重做与高效校对**：新增按钮及 Ctrl＋Z / Ctrl＋Y，最多保留80个内存历史状态，可恢复条目、层级、映射及确认状态。增加标题查找、全部/待确认/低可信/未知页码筛选、“下一待核对”及详细表格/目录树切换；筛选保持原条目对应，不重排、不重编号，不改变目标页或确认状态。未填完的无效输入保留，避免切换时误应用。
5. **原目录行定位与预览工具**：在已有滚轮、Ctrl＋滚轮和50%–300%缩放上，增加“适合宽度”“整页”“上一页”“下一页”。“原目录行”回到识别来源页并标示实际来源区域；未知来源或导入条目不伪造定位。页码映射/高级默认折叠，展开后继续使用原固定偏移和分段映射规则。
6. **逐页人工区域和栏线**：可在目录页预览中框选识别区域、点击设置分栏线，各页分别保留设置，下一次识别时应用，也可清除此页设置。人工分栏补读收紧外侧空白并保留指定栏缝，修复宽白边造成整行漏检。设置只约束识别范围，不修改 PDF，不直接改变已有条目、层级或正文页码映射；重新识别前请先保留当前编辑。
7. **资源与生命周期修复**：合并过期渲染请求，关闭时释放预览图片、排队结果、撤销历史及自有变量/按键回调，解除工作台父回调引用。取消尚未执行的初始 JSON 载入，修复快速关闭后的失效回调，以及关闭已取消读取的工作台后主界面仍被阻断的问题。没有预缓存整本 PDF，未实现按视口裁剪渲染，不承诺固定内存或速度改善比例。

本版相对正式 v1.6.0 包含上述草稿、校对、人工区域识别与标签页更新。沿用既有 `ttk.Notebook`、PyMuPDF 和本地 OCR，没有新增外部框架、模型、运行依赖或第三方代码复制；原有来源与许可记录继续保留。

## 继续保留的规范与功能

- 自动/单栏/双栏布局；双栏按完整左栏再完整右栏读取，章节上下文跨栏、跨页继续，栏位置本身不决定层级。
- 三种节编号：默认 `1.1 基本概念`、每章独立的 `1. 基本概念`、保留识别编号；编号与标题间一个空格，省略数字号前 `§`。原有可靠编号与手工编辑保护继续有效，标题变化后重新确认。
- 正式目录 JSON `version: 1`、CLI 参数、固定/分段页码映射、目标页确认、批量配对和默认跳过已有书签。
- 预览只读；PDF 仍按原路径临时副本写入、校验后原子替换。备份默认开启，删除输入 JSON 和茉莉花缓存仍为两个独立、默认关闭的成功后选项。
- 原 `%LOCALAPPDATA%\ZoteroPDFBookmarks\settings.json` 与 `CONFIG_SCHEMA=1`，无需迁移。草稿使用独立文件，不改变正式 JSON 或设置 schema。
- 原 Single/Portable 更新事务、下载校验、健康检查及程序/配置同步回滚。源码直接调用 `open_editor()` 的独立窗口入口继续兼容。

## 使用方法

1. 打开“目录工作台 · 生成与编辑”，或从主界面点击“生成 / 编辑目录…”，选择/拖入原 PDF；已有 JSON 时可一起拖入。
2. 填写实际 PDF 目录页范围，选择布局和节编号。自动判断不理想时可选单栏/双栏，或先逐页框选区域、设置栏线，再重新识别。新识别会替换当前目录，先保存需要保留的编辑。
3. 在表格或目录树中校对标题、层级与目标页；用筛选、“下一待核对”、来源行和目标页预览检查。按需撤销/重做；暂存可保存未完成工作，但不替代正式导出。
4. 需要稍后继续时暂存，重新打开同一 PDF 后点“恢复草稿”。两标签普通切换保留当前内容；关闭工作台或整个程序时注意保存/取消提示。
5. 核对并确认所有有效目标页后保存 JSON，程序回主界面自动预览。检查无误后再点“写入勾选的 PDF”，在阅读器重新打开原文件查看书签。

普通 PDF 无需安装 Zotero。处理 Zotero 附件时，用“显示文件”定位原 PDF，关闭该 PDF 阅读窗口后处理，再重新打开同一附件，无需重新附加。启用可选茉莉花缓存清理前须完全退出 Zotero。

## 兼容性与限制

自动结果仍是待校对草稿，可信提示不是准确率保证。跨栏长标题、同页混合单/双栏、模糊扫描、数学符号、上标、缺页及未标印刷页码条目可能需要手工处理；区域和栏线不能代替层级、标题与实际目标页核对。识别不等于已逐页校验正文，保存前应抽查章首、跨栏衔接和末尾页。

所有 OCR、草稿与处理均在本机运行，不上传 PDF，不需要 API Key。草稿可能含文献标题和本地路径，属于用户未完成工作，不应作为构建临时文件清理。仅复制 EXE 不会带走本机设置与草稿；恢复草稿还需原 PDF 路径、大小和修改时间匹配，不应视作跨电脑迁移格式。

## 从旧版升级

v1.5.0 及后续 Single/Portable GUI 可通过“帮助 / 更新”检查已公开正式版本，下载校验后由用户选择安装并重启，保留发行类型、用户改名后的入口和原设置。安装前保存目录并关闭工作台内容，等待识别、预览、保存和 PDF 写入任务结束；切回主界面并不等于已关闭工作台。CLI/源码从发行页手动更新。

v1.4.1 没有自动更新入口，须手动下载本版。Single 运行新 EXE；Portable 完整解压新文件夹，不能只复制主 EXE。旧程序目录中用户自行保存的 PDF、目录 JSON、备份与其他资料继续保留。

## 验证与证据范围

- **源码回归**：发布准备时已完成477项，476通过、1项跨盘环境测试跳过、0失败；包括21项新增真实 Tk 标签页回归。覆盖切页保留、生命周期、快捷键/拖放、保存返回、任务互锁、配置及已有 PDF/CLI/更新回归。跳过项不算通过。
- **同功能试用包**：此前本地1.6.0版本身份试用 EXE 的237项包内模块检查通过，使用宿主依赖；它与正式1.7.0的身份不同，不能替代正式包检查。实际试用 EXE 使用合成 PDF，验证两页切换、来源定位、滚动/缩放、7项目录确认保存回主预览、旧 JSON 载入、正常/最小尺寸和关闭；原 PDF 与真实用户设置哈希未变。
- **真实双栏样例**：上一阶段只读识别《实分析与复分析》实际 PDF 第7–8页，自动与人工栏线均147项（含“目录”入口）、20章、偏移+8，层级/目标页与独立参照一致，源 PDF 不变；原有书签仅作独立核对。译者序、关于作者、前言无印刷页码，须手工补录；数学符号与错字仍需核对。该证据不等于本版冻结 GUI 的实书 OCR 操作。
- **正式1.7.0本地候选**：四种生产身份/资源、内嵌helper与26项源码指纹核验通过；正式Single内嵌模块237项检查通过。冻结CLI预览、原路径写入、原字节备份和默认跳过通过；真实冻结1.7.0→隔离合成1.7.1的Single/Portable成功升级与健康失败回滚共4场景通过。合成版本不发布。正式构建与前述已验收试用的运行源码仅VERSION变化。七项附件、manifest、校验清单和ZIP完整性在本地核验；云端重新构建、验收并检查草稿资产后才公开，结果以 [VALIDATION.md](https://github.com/Zerozero05/PDF_Bookmarks/blob/v1.7.0/VALIDATION.md) 和对应 [Windows Actions](https://github.com/Zerozero05/PDF_Bookmarks/actions/workflows/windows-build.yml) 为准，不把本地哈希当云端产物哈希。
- **路径限制**：仍受Windows路径长度限制；过深的程序/临时目录可能导致文件操作失败，应使用较短的目录。首次集成的隔离测试目录过深，缩短D盘测试profile后，相同四场景通过，未放宽检查。
- **未覆盖边界**：完整冻结 GUI 的真实书籍 OCR 与 PDF 写入交互未逐项实操；Ctrl＋滚轮等已有事件由源码/包内 Tk 检查覆盖。单个实书与合成场景不保证任意文档或 Windows 环境绝无缺陷。
